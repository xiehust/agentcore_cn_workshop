# PRD：门户增加分析会话与历史功能

## 背景与问题

Part 2 分析门户目前的对话是"一次性"的：

- 会话内多轮历史只存在 Runtime microVM 的模块级 dict（`agent/main.py` 的 `_HISTORY`），
  microVM 回收（idle 约 15 分钟 / 最长 8 小时）后上下文丢失；
- 前端刷新页面 / 点「新对话」后，旧对话在界面上彻底消失，无法回看；
- 没有会话列表，用户无法在多个分析主题之间切换。

任务管理模块（08-08）已经验证了「HTTP API + Lambda + Aurora（RDS Data API）」
的门户后端模式，本任务复用该模式给对话加持久化。

## 目标（MVP 范围）

1. **会话持久化**：每轮对话（用户输入 + Agent 回复，含中间工具消息）落库 Aurora，
   页面刷新 / microVM 回收后不丢。
2. **历史会话列表**：门户侧栏展示当前用户的历史会话（标题 + 最后活动时间），
   按最后活动倒序。
3. **恢复会话**：点击历史会话可回看完整对话（Markdown / chart 渲染同现有消息），
   并能**继续追问**——Runtime 侧从库里回灌历史，上下文延续（多轮记忆不断档）。
4. **会话管理**：新建会话（现有「新对话」按钮语义不变）、重命名、删除（软删）。
5. **会话标题**：默认取首条用户输入截断生成，支持手动重命名。

## 非目标

- 不做跨用户共享 / 协作会话；
- 不做长期语义记忆（mem0 仍是预留，见 `agent/main.py` 标注）；
- 不做会话内消息级操作（编辑 / 重发 / 删除单条消息）；
- 不做全文搜索；
- CLI（`chat_test.sh`）会话不要求出现在门户列表里，但不能被本功能破坏。

## 用户故事

- 作为分析师，我昨天做过一轮选品漏斗分析，今天打开门户还能找到那个会话，
  点开接着问"和上周比呢"，Agent 记得之前聊过什么。
- 作为分析师，我同时跟进两个赛道，可以在两个会话之间切换，各自上下文独立。
- 作为分析师，我可以把不再需要的会话删掉，把重要会话改成好记的名字。

## 验收标准

1. 在门户发起对话并收到回复后**刷新页面**：侧栏历史列表出现该会话，
   点开能看到完整对话（含 chart 代码块正常渲染成图表）。
2. 对一个**超过 15 分钟无活动**（或用新部署顶掉 microVM）的历史会话继续追问，
   Agent 的回答能体现之前的上下文（如"刚才那个漏斗"能被理解）。
3. 「新对话」创建新会话；旧会话仍在列表中可回切，两边消息互不串。
4. 重命名后列表即时更新；删除后会话从列表消失（库里软删，数据保留）。
5. 会话列表只显示当前登录用户（Keycloak `preferred_username`）的会话。
6. `./scripts/chat_test.sh` 单轮与多轮（带 session id）行为不回归。
7. `npm run build`（tsc 类型检查）通过；部署脚本幂等可重跑。

## 约束

- 遵循项目既有约定：中文文档 / commit、文档不出现真实端点、门户「量化工作台」
  暗色风格（新 UI 元素不引入新的美学方向）。
- 后端沿用「不进 VPC、RDS Data API」访问 Aurora 的既有路线。
- Runtime 落库必须 best-effort：持久化失败不能阻断聊天主链路（SSE 流照常返回）。
