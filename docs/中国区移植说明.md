# 中国区移植说明

本文档记录本 workshop 从全球区移植到中国宁夏区（`cn-northwest-1`）的设计原则、
分区差异与实测结论。动手操作见根目录 [实验手册.md](../实验手册.md)；架构详解见
[架构与设计.md](架构与设计.md)。

## 现状

AgentCore 已在宁夏区（`cn-northwest-1`）上线并经本仓库全量实测（2026-09）：
**Runtime / Browser / Gateway / Identity / Code Interpreter 可用；托管 Memory
暂未上线**——本仓库长期记忆用自建 mem0，不受影响。宁夏区没有原生 Bedrock
模型服务（`bedrock` / `bedrock-runtime` 端点不存在），模型必须走区内可达的
OpenAI 兼容端点。

两个分区共用同一套代码，**区域代码（`AWS_REGION`）是唯一开关**：部署脚本按
区域自动推导 ARN 分区（`arn:aws-cn`）、域名后缀（`.amazonaws.com.cn`）与
AgentCore SDK 端点覆盖（`BEDROCK_AGENTCORE_CP_ENDPOINT` / `DP_ENDPOINT`）。

## 两分区通用的设计形态

- **数据面零 RDS Data API**（中国区没有该服务，已实证）：实验一走写库 Lambda；
  实验二的会话历史（Runtime）、任务表（tasks-api / runner）统一经通用数据面
  Lambda（`agentcore-workshop-db`，`op=execute` 协议、pg8000 直连），部署预检
  走写库 Lambda 的 `check_tables`。集群 `EnableHttpEndpoint` 与
  `AgentDataAccessPolicy` 已删除。
- **模型统一标准 OpenAI 兼容端点 + key**：三元组
  `OPENAI_BASE_URL` / `OPENAI_API_KEY` / `MODEL_ID` 环境变量注入，
  IAM 铸 token 路径已移除。中国区 export 区内模型网关的三元组即可；
  模型侧实测约束（工具 schema 净化、reasoning 参数）见
  [架构与设计.md](架构与设计.md#模型接入设计)。
- **部署形态 direct_code_deploy**：`agentcore configure` 显式
  `--deployment-type direct_code_deploy`（依赖由 `uv` 本机打包，无需 Docker、
  不经 CodeBuild）——**aws-cn 没有 CodeBuild ARM_CONTAINER**，toolkit
  0.3.13 起的默认 container 模式在中国区必然失败。
- **Gateway 零 VPC egress**：私网访问全部由 VPC 内 Lambda 承担，不依赖
  Gateway 的 VPC 出口能力。
- **认证自部署 Keycloak**（中国区没有 Cognito）：OIDC 全链路不依赖海外托管
  服务；HTTPS 入口用 API Gateway HTTP API 默认域（AWS 侧已备案，免自备域名）。
- **长期记忆自部署 mem0**：向量存 Aurora pgvector、经 VPC 内 Lambda 读写；
  提取 LLM 与 embedding 走 OpenAI 兼容端点（`MEM0_*` 环境变量），中国区换
  端点即可。换 embedding 模型若维度变化，需换 `MEM0_COLLECTION` 重建向量表。
- **端口体系避开备案限制**：未备案账号 80/8080/443 被封，CloudLab 的 IDE
  入口（8889）、HTTPS 门户（8443）、HTTP 门户（NLB:5173）全部使用非标准
  端口；中国区 CloudFront 必须绑定已备案域名，故对外服务不走 CloudFront。

## 宁夏区实测差异与修复（2026-09）

以下为宁夏区全量部署实测中定位并已修复的分区差异，**均已进主线代码**：

| 差异 | 现象 | 修复 |
|------|------|------|
| 接口端点服务名**按服务不一致** | `cn.com.amazonaws.<region>.secretsmanager` 不存在，建栈 400 | secretsmanager 在两个 cn 区实测均为 `com.amazonaws` 前缀（无 `cn.`），模板与脚本按实测写死；execute-api / lambda 则确带 `cn.` 前缀——不能按「中国区统一加前缀」推断，逐服务 `aws ec2 describe-vpc-endpoint-services` 实测为准 |
| IAM service principal 形态 | `lambda.${AWS::URLSuffix}` 在 cn 展开为 `.com.cn` 不被接受 | lambda 等多数服务硬编码 `.amazonaws.com`；EC2 保留 URLSuffix（cn 确为 `ec2.amazonaws.com.cn`，唯一例外）；`iam:PassedToService` 双写两种形态兜底 |
| 账户级 IMDSv2 强制 | `httpTokensEnforced` 开启的账号，IMDSv1 启动请求直接 400 | IDE 实例经最小 LaunchTemplate 注入 `HttpTokens=required`（两分区通用的安全默认） |
| CodeBuild ARM_CONTAINER 缺失 | `agentcore launch` 默认 CodeBuild 模式报错 | 三处 `agentcore configure` 显式 `--deployment-type direct_code_deploy`；venv 预装 `uv`（该模式打包依赖的硬前置） |
| 模型端点严格 schema 校验 | 工具 schema 含 `"format": "binary"`（strands_tools Code Interpreter 自带）时整个请求 400，strands 吞成空事件流（Agent 静默零输出） | 两个 Agent 统一 `_sanitize_tool_schema` 剥 `format` 键（JSON Schema 中为可选注解，无语义损失） |
| Keycloak 基础镜像 quay.io 区内极慢 | 实验二 docker build 拉底镜像僵死 | CloudLab bootstrap 从区内资产 CDN 预载镜像 tar 并 `docker load`，构建走本地缓存（预载失败自动回退直拉）；自备机器部署时建议先手动转存镜像 |
| 建栈资产跨境下载 | code-server rpm（GitHub）/AWS CLI/代码包走跨境，慢且易致 bootstrap 超时回滚 | 资产统一区内 CDN 分发（`publish-assets.sh` cn 通道 + `deploy-ide.sh` 内置默认地址）；bootstrap 配 pip（TUNA）/npm（npmmirror）镜像源 |

## 宁夏区实测结论（2026-09-29）

- **端到端全通**：CloudLab 建栈 → 基础环境 → 实验一（Browser 实爬 eBay UK，
  含人机验证兜底口径，判定与候选档案入库）→ 实验二（Keycloak on Fargate
  ARM64、Gateway MCP 工具、Identity M2M、mem0 记忆种子与现场沉淀、门户
  三账号浏览器 E2E 全部通过）。
- **服务可用性**：Aurora PostgreSQL 17.x + db.serverless + 托管主密码、
  NLB 挂安全组、EventBridge Scheduler、Fargate ARM64 均可用。
- **出网可达性**：AgentCore Browser 从宁夏区访问 eBay UK/US 可用；跨境链路
  有波动，单商品处理 2~5 分钟属正常，遇反爬验证时 Agent 按 SOP 保守兜底。
- 模型经区内 OpenAI 兼容网关（推理模型 + 1024 维 embedding），工具调用、
  流式输出、mem0 事实提取全部验证通过。
