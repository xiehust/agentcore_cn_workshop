# Amazon Bedrock AgentCore Workshop 运行手册（VS Code IDE Server 版）

本手册指导你在自己的 AWS 账号里：

1. 部署 **CloudLab 单栈**（`cloudformation/cloudlab-template-china.yaml`）：
   一个栈同时包含浏览器版 VS Code IDE Server（code-server on EC2，经 ALB 访问，
   实例挂载按最小权限收敛的 IAM 角色）与 workshop 数仓基础设施
   （私有 VPC + Aurora Serverless v2 + Secrets 端点）；**删除这个栈即可一键
   销毁全部资源**（栈内清理钩子会连带清掉步骤脚本创建的所有 workshop 资源）；
2. 在 IDE 的 Terminal 里分三步完成 AgentCore Workshop：
   **部署基础环境 → 运行场景 1（选品数据摄入 Pipeline）→ 运行场景 2（Web Chat 分析门户）**。

区域是唯一开关：全球区用 `us-west-2`（已验证），中国区用 `cn-northwest-1`
（宁夏区已验证）。所有脚本按 `AWS_REGION` 自动推导分区（`arn:aws-cn`）、
域名后缀（`.amazonaws.com.cn`）与 SDK 端点覆盖；中国区建栈资产（代码包、
Lambda zip、code-server rpm、AWS CLI、Keycloak 基础镜像）全部走区内 CDN
镜像（`deploy-ide.sh`/模板已内置默认地址；`ASSET_SOURCE=mirror` 可切到内容
一致的全球镜像，`ASSET_BASE_URL` 可整体覆盖）。

## 0. 总览

```
CloudLab 单栈（agentcore-workshop-base）＝ IDE + 数仓基础环境 + 删除清理钩子
你的浏览器 ──HTTP:8889──▶ ALB ──8889──▶ EC2（code-server IDE，最小权限 IAM 角色）
（入口用非标准端口 8889：中国区未备案账号被封 80/8080/443，非标准端口不受限）
                                     │ IDE Terminal 内执行：
                                     ├─ 01_deploy_base.sh    基础环境（写库 Lambda + 建表；VPC/Aurora 已随栈建好）
                                     ├─ 02_run_scenario1.sh  场景1（Browser/Profile + 摄入 Agent + 冒烟调用）
                                     ├─ 03_run_scenario2.sh  场景2（Keycloak + Gateway + Identity + 分析 Agent + 门户）
                                     └─ 99_cleanup.sh        仅重置两个场景（保留基础栈）
删除单栈 = 一键销毁（清理钩子自动清掉步骤脚本创建的全部 workshop 资源）
```

| 阶段 | 耗时（约） | 是否需要模型 key |
|------|-----------|------------------|
| 部署 CloudLab 栈（IDE + Aurora + Keycloak 基础设施 + 数据面 Lambda/建表 + venv 全预制） | 15-20 分钟 | 否 |
| 01 基础环境自检/修复（**可选**——栈创建已包含全部基础环境） | 2-3 分钟 | 否 |
| 02 场景 1 | 部署 3-5 分钟 + 冒烟调用 2-5 分钟 | **是** |
| 03 场景 2 | 8-12 分钟 | **是** |

## 1. 前置条件

**操作员机器**（部署 IDE 用，之后所有操作都在 IDE 里）：

- AWS CLI v2，已 `aws configure` 配好目标账号凭证（部署 IDE 栈需要较高权限，
  建议管理员或等效权限；**IDE 实例本身**只拿最小权限角色）
- 本目录结构完整：`agentcore_cn_workshop/` 与 `agentcore_cn_hands_on/` 位于同一父目录

**模型访问**（场景 1/2 需要，二选一）：

- **全球区（默认）**：Bedrock 控制台 → Model access → 开通 **OpenAI GPT-5.6**；
  然后 Bedrock 控制台 → **API keys** → 生成长期 API key（`ABSK` 前缀）。
  使用时 `export AWS_BEARER_TOKEN_BEDROCK=<ABSK开头的key>`
- **中国区 / 自定义端点**：任意 OpenAI 兼容 Chat Completions 服务，
  `export OPENAI_BASE_URL=<https://.../v1> OPENAI_API_KEY=<key> MODEL_ID=<模型名>`
  （推荐改填 workshop 根的 `.env`——CloudLab 建栈已预制该文件、脚本自动加载，免逐 Terminal export）

**（可选）打开场景 2 的 Web 门户**：你的笔记本需要 AWS CLI +
[Session Manager 插件](https://docs.aws.amazon.com/systems-manager/latest/userguide/session-manager-working-with-install-plugin.html)（做 5173 端口转发）。

## 2. 第一步：部署 CloudLab 单栈（IDE + 数仓基础环境）

在操作员机器上：

```bash
cd agentcore_cn_hands_on/ide
AWS_REGION=us-west-2 bash deploy-ide.sh
```

中国区（宁夏）示例——资产镜像与 code-server rpm 地址已内置默认值
（区内 CDN，可用 `ASSET_BASE_URL` / `CODE_SERVER_RPM_URL` 覆盖）：

```bash
AWS_REGION=cn-northwest-1 bash deploy-ide.sh
```

资产有两个内容一致的分发源，`ASSET_SOURCE` 一个变量成对切换
`AssetBaseUrl` 与 code-server 地址：

| `ASSET_SOURCE` | 分发源 | 用途 |
|---|---|---|
| `cn` | 中国区 CDN（备案别名域，HTTP） | **默认**（所有区域，与模板 `AssetBaseUrl` 默认值一致） |
| `mirror` | 全球区账号镜像（CloudFront 默认域名 + 专用私有桶，HTTPS） | 备用，显式切换（每次发布自动同步，随时可切） |

```bash
# 中国区改用全球镜像（例如区内 CDN 不可用时；跨境下载，建栈会慢一些）
ASSET_SOURCE=mirror AWS_REGION=cn-northwest-1 bash deploy-ide.sh
```

> 发布走 `publish-assets.sh`：一次构建，**本次消费的通道为必需、另一通道附带
> 同步**（`deploy-ide.sh` 自动设置；附带通道凭证不可用或失败只告警），两边内容
> 始终一致。单独补发某个通道：`PUBLISH_TARGET=mirror bash publish-assets.sh`。
> 代码包与 Lambda zip 每次发布；`tools/` 下三个大文件（awscli / code-server rpm /
> keycloak 镜像 tar）由维护者一次性上传到两个桶（jumphost 下载 + 预签名 URL
> 直传；预签名须用区域端点，新桶的全局端点 DNS 未传播时会 307），脚本只校验存在性。

可选环境变量：

| 变量 | 默认 | 说明 |
|------|------|------|
| `WORKSHOP_STACK_NAME` | `agentcore-workshop-base` | 栈名（须以 `agentcore-workshop` 开头，最小权限按该前缀收敛） |
| `ASSET_SOURCE` | `cn` | 资产分发源（`cn` / `mirror`），见上表；`ASSET_BASE_URL` 显式设置时优先 |
| `ALLOWED_CIDR` | `0.0.0.0/0` | 允许访问 IDE 的来源 IP 段，**强烈建议收敛**（如 `1.2.3.4/32`） |
| `IDE_INSTANCE_TYPE` | `t3.large` | 实例类型 |
| `IDE_ALB_PORT` | `8889` | IDE 入口端口。默认非标准端口 8889（中国区未备案账号被封 80/8080/443）；全球区测试可传 `80`，兼容只放行 80/443 出站的办公网络 |
| `ENABLE_PUBLIC_PORTAL` | 关闭 | 设为 `1` 时公网化场景 2 的 Web 门户（**HTTPS**）：自动生成自签证书导入 ACM，ALB 加 8443 HTTPS 监听器转发 Vite（登录仍是 Keycloak PKCE；8443 非标准端口中国区免备案；浏览器首次访问需点掉自签证书告警） |
| `ENABLE_HTTP_PORTAL` | 关闭 | 设为 `1` 时公网化场景 2 的 Web 门户（**纯 HTTP**，NLB TCP:5173 直通实例）：免备案、免证书告警，中国区最顺滑；前端在非安全上下文自动退回无 PKCE 的授权码流程。⚠️ token 明文传输，仅限 workshop 演示 |

脚本做三件事：打包 workshop 代码上传 S3 → 部署单栈
`cloudformation/cloudlab-template-china.yaml`（IDE + VPC + Aurora Serverless v2 +
**Keycloak 基础设施**（ECS Fargate 0 副本待命 + API Gateway HTTPS 入口，
场景 2 推完镜像后拉起）+ 删除清理钩子）→ 打印 IDE 地址与取密码命令。

> 手动方式：也可以在 CloudFormation 控制台直接上传
> `cloudlab-template-china.yaml`，参数 `WorkshopAssetsBucket/WorkshopAssetsKey`
> 指向你自行上传的代码包
> （`tar czf workshop-assets.tar.gz agentcore_cn_workshop agentcore_cn_hands_on`）。

**登录 IDE**：

```bash
aws secretsmanager get-secret-value --secret-id agentcore-workshop-base-ide-password \
  --region us-west-2 --query SecretString --output text
```

浏览器打开部署输出里的 `IdeUrl`（形如 `http://<alb-dns>:8889/?folder=/home/ec2-user/environment`），
输入上面 JSON 里的 `password` 字段。左侧工作区能看到 `agentcore_cn_workshop`
目录即部署成功（步骤分步脚本就在工作区 `agentcore_cn_workshop/scripts/` 下（文件树可见），
Terminal 里直接 `bash ~/environment/agentcore_cn_workshop/scripts/...` 调用）。

## 3. 第二步：部署基础环境（IDE Terminal 内）

IDE 菜单（左上 ≡）→ Terminal → New Terminal：

```bash
bash ~/environment/agentcore_cn_workshop/scripts/01_deploy_base.sh
```

完成内容：Python venv + agentcore CLI 安装、写库 Lambda
`agentcore-workshop-writer`（挂进栈里建好的私有 VPC，pg8000 直连 Aurora）、
建 7 张表（两个场景共用数仓）。VPC/Aurora/Secrets 端点已随 CloudLab 栈建好，
本步只补数据面。**此步不需要模型 key**，幂等可重跑。

成功标志：末尾输出 `✅ 基础环境部署完成！`。

## 4. 第三步：运行场景 1 —— 选品数据摄入 Pipeline

场景 1 链路：调用方 → AgentCore **Runtime**（Strands Agent + 选品 SOP Skill）→
**Browser** 爬 eBay / **Code Interpreter** 沙箱测算 → 写库 Lambda → Aurora。

```bash
# 先配置模型 key（全球区示例；中国区改 export 三元组）
export AWS_BEARER_TOKEN_BEDROCK=<ABSK开头的key>

bash ~/environment/agentcore_cn_workshop/scripts/02_run_scenario1.sh
```

完成内容：自定义 Browser（Web Bot Auth 请求签名，过 Cloudflare/Akamai 反爬）+
Browser Profile（跨会话保留 cookies）、`agentcore configure/launch` 部署
`product_ingestion_agent`、Runtime 执行角色附加写库/浏览器策略，最后自动做一次
**真实冒烟调用**（爬 eBay 1 个商品并入库，约 2-5 分钟；`SKIP_SMOKE=1` 可跳过）。

之后可自行体验更多调用（每个商品 2-5 分钟）：

```bash
cd ~/environment/agentcore_cn_workshop/part1_data_ingestion/agent
source ../../.venv/bin/activate && source ../scripts/cn_env.sh
agentcore invoke '{"prompt": "从 eBay 美国站搜索 cable organizer 选品，处理前 2 个非广告商品"}'
```

数据入库验证（`agentcore-workshop-db` Lambda 由场景 2 部署，若尚未跑场景 2 可先跳过）：

```bash
aws lambda invoke --function-name agentcore-workshop-db --region "$AWS_REGION" \
  --cli-binary-format raw-in-base64-out \
  --payload '{"op":"execute","args":{"sql":"SELECT product_title, verdict, product_points FROM selection_verdicts ORDER BY created_at DESC LIMIT 5","params":{}}}' \
  /dev/stdout
```

## 5. 第四步：运行场景 2 —— Web Chat 分析门户

场景 2 链路：SPA（PKCE 登录）→ 自部署 Keycloak（ECS Fargate）→ Runtime
（分析 Agent，JWT 入站）→ Identity（M2M）→ **Gateway**（MCP 工具）→
Lambda(VPC) → Aurora；另含 Code Interpreter 统计分析、自建 mem0 长期记忆、
数据摄入任务管理模块（EventBridge Scheduler 定时调度场景 1 的 Agent）。

```bash
# 模型 key 同场景 1；可选：配置 mem0 长期记忆（缺省禁用，不影响对话）
# export MEM0_LLM_MODEL=... MEM0_LLM_BASE_URL=... MEM0_LLM_API_KEY=... MEM0_EMBEDDER_MODEL=...

bash ~/environment/agentcore_cn_workshop/scripts/03_run_scenario2.sh
```

脚本调用 workshop 原版 Part 2 一键部署（10 步，首次会对任务栈部署两遍——正常现象），
随后预装前端依赖。不做自动冒烟；需要命令行验证时手动执行
`part2_chat_portal/scripts/chat_test.sh '你的问题'`。

**打开 Web 门户**——Keycloak PKCE 登录要求安全上下文（HTTPS 或 localhost），
两种方式二选一，前置都是先在 IDE Terminal 里启动前端：

```bash
cd ~/environment/agentcore_cn_workshop/part2_chat_portal/web && npm run dev
```

- **方式 A：公网 HTTPS 入口**（部署 IDE 栈时带了 `ENABLE_PUBLIC_PORTAL=1`）：
  浏览器直接打开栈输出 `PortalUrl`（`https://<alb-dns>:8443`），自签证书首次
  访问在告警页点「高级 → 继续前往」即可。`03_run_scenario2.sh` 会自动把该地址
  加进 Tasks API 的 CORS 白名单。
- **方式 B：SSM 端口转发**（默认，零公网暴露）：你的笔记本上执行
  （`<instance-id>` 见栈输出 `IdeInstanceId`）：
  ```bash
  aws ssm start-session --target <instance-id> --region us-west-2 \
    --document-name AWS-StartPortForwardingSession \
    --parameters '{"portNumber":["5173"],"localPortNumber":["5173"]}'
  ```
  然后浏览器打开 `http://localhost:5173`。
- **方式 C：公网 HTTP 入口**（部署 IDE 栈时带了 `ENABLE_HTTP_PORTAL=1`，
  中国区最顺滑——免备案、免证书告警）：浏览器直接打开栈输出
  `HttpPortalUrl`（`http://<nlb-dns>:5173`）。前端检测到非安全上下文会自动
  退回无 PKCE 的授权码流程（realm 已不强制 S256）。
  ⚠️ HTTP 下账号密码与 token 明文传输，仅限 workshop 演示环境；
  若在改动 realm 前已部署过 Keycloak，需 `KC_REDEPLOY=1` 重跑一次
  （维护操作：会重建镜像并 `ecs update-service`，受管账号需有该权限/用豁免身份）
  `03_run_scenario2.sh` 让新 realm 生效。

登录用 `analyst`（密码见 IDE 内 `part2_chat_portal/.deploy/secrets.env`）。

试试这些对话：「看下最近30天的选品漏斗」「按站点统计通过率」。

**长期记忆多账号演示**（需已配 `MEM0_*`）：先
`python3 scripts/seed_memories.py` 预置 `vivian`（资深买手）与 `marco`（风控合规）
的偏好记忆，再分别登录，观察同一问题得到的差异化回答。

**任务管理**：门户左侧「任务」页可把场景 1 的摄入任务做成一次性/定时调度
（EventBridge Scheduler → runner Lambda → 场景 1 Runtime）。

## 6. 资源清理

**一键全部销毁**（推荐）——删除 CloudLab 单栈即可。栈内的 `CleanupOnDelete`
钩子会先自动清理步骤脚本创建的全部资源（调度、6 个 Lambda、AgentCore
Runtime/Browser/Gateway/Identity、part2 的 2 个子栈（Keycloak 基础设施已随 base 栈托管）、ECR 仓库、SDK 角色、
残留 ENI），随后栈内 IDE/VPC/Aurora 一并删除：

```bash
# 操作员机器上（或直接在 CloudFormation 控制台删除栈）
cd agentcore_cn_hands_on/ide && AWS_REGION=us-west-2 bash destroy-ide.sh
```

> 若删除因 Lambda ENI 异步回收超时失败，重试一次删栈即可收敛。

**仅重置两个场景**（保留 IDE 与数仓，便于重新练习）：

```bash
# IDE Terminal 内
bash ~/environment/agentcore_cn_workshop/scripts/99_cleanup.sh
```

## 7. 最小权限说明（IDE 实例角色）

IDE 实例角色（栈输出 `IdeRoleArn`）相比原 openclaw 模板做了大幅收敛，
拆为 3 个客户托管策略：

| 策略 | 范围 |
|------|------|
| `*-workshop-infra` | CloudFormation 仅限 `stack/agentcore-workshop-*`；EC2-VPC/RDS 按动作枚举且限定本区域；Secrets Manager 仅 `rds!*` 前缀（RDS 托管主密码所需）；KMS 写操作用 `kms:ViaService` 收敛到本区域 RDS/Secrets Manager（加密 Aurora 所需）；Scheduler 仅 `agentcore-workshop-*` |
| `*-workshop-iam` | 角色管理仅 `agentcore-workshop-*` 与 `AmazonBedrockAgentCoreSDK*`；`iam:PassRole` 附 `iam:PassedToService` 条件（lambda/ecs-tasks/scheduler/codebuild/bedrock-agentcore） |
| `*-workshop-app` | Lambda 仅 `agentcore-workshop-*`；ECR 仅 `agentcore-workshop*` 与 `bedrock-agentcore-*`；`bedrock-agentcore:*` 限定本区域；CodeBuild/S3 仅 `bedrock-agentcore-*`（starter toolkit 产物） |

明确未授予（openclaw 模板遗留、本 workshop 用不到）：`eks:*`、`sqs:*`、
`wafv2:*`、`elasticfilesystem:*`、`elasticloadbalancing:*`、`kms:*`、
`ec2:RunInstances` 等。

## 8. 排障速查

| 症状 | 处理 |
|------|------|
| IDE 打不开 / 502 | 栈刚建好时 bootstrap 还在跑，等 2-3 分钟；仍不行看实例 `/var/log/ide-bootstrap.log`（SSM Session Manager 连进去） |
| IDE 地址一直超时（服务端目标 healthy） | 入口是非标准端口 8889（为中国区免备案），部分企业办公网只放行 80/443 出网——换网络（手机热点/家庭网）或走 VPN 即可 |
| IDE 密码不对 | 重新取 secret，注意复制 JSON 里 `password` 字段的值而非整段 JSON |
| 脚本报 AccessDenied | IDE 角色是最小权限——确认操作的资源名带 `agentcore-workshop` 前缀；自定义改名需同步放宽 `ide/vscode-ide-server.yaml` 里的策略 |
| `缺少模型 API key` | `export AWS_BEARER_TOKEN_BEDROCK=<ABSK key>`（或三元组）后重跑 02/03 |
| 调用 401 invalid_api_key | key 失效或用了 `sk-` 假 key；换 Bedrock 控制台生成的 `ABSK` key 并重跑 02/03（key 会烧进 Runtime 环境变量） |
| `agentcore: unknown command 'configure'` | npm 同名包遮蔽，脚本已自动用 venv 内 CLI；手动操作时先 `source ~/environment/agentcore_cn_workshop/.venv/bin/activate` |
| 场景 2 冒烟 403 | Keycloak 刚就绪需要约 1 分钟；或重跑 `03_run_scenario2.sh`（幂等，会同步 authorizer） |
| 门户空白页 / redirect_uri 报错 | 必须用 `http://localhost:5173`（端口转发后），不能用 IP 或 ALB 地址 |
| docker 命令 permission denied | 重开一个 Terminal（bootstrap 已把 ec2-user 加入 docker 组，新会话生效） |
| 中国区特有问题 | Keycloak 基础镜像已由 IDE bootstrap 从区内 CDN 预载（`docker load`），场景 2 构建不再访问 quay.io（预载失败才回退直拉）；`cn_env.sh` 已被脚本自动 source；详见 workshop 根 README「中国区移植说明」 |

更深入的排障见 `agentcore_cn_workshop/实验手册.md` 的「排障速查」章节。

## 9. 活动前容量验证（中央 Keycloak / 模型网关）

全场学员共用两个外部依赖：中央 Keycloak（登录、签发 token）与 OpenAI 兼容
模型网关（Agent 推理 + mem0 embedding）。活动前在压测机上用 `loadtest/` 两个
脚本按 ~100 人峰值形态各压一轮。两个脚本都是**有界压测**（请求总数固定）；
模型网关脚本先发预检请求，场景内错误率过半自动停止。

```bash
# 中央 Keycloak（压测机需 ab：sudo dnf install -y httpd-tools）；两行凭证走 stdin
printf '%s\n%s\n' "$ANALYST_PASSWORD" "$AGENT_CLIENT_SECRET" | \
  KC_URL=https://<api-id>.execute-api.cn-northwest-1.amazonaws.com.cn bash loadtest/kc_loadtest.sh

# 模型网关（变量名与 .env 一致；key 从 stdin 读。压测机若残留同名
```

### 2026-10-09 实测（并发 100，压测机 us-west-2）

**中央 Keycloak**（单副本，扩容前后各压一轮）：两轮各 7200 请求零失败（API
Gateway 4xx/5xx 均为 0，压测期间任务未重启）。时延含 us-west-2 → 宁夏跨境往返
约 0.2s。吞吐与时延（p50 / p99）：

| 场景 | 请求数 | 1 vCPU / 2GB | 2 vCPU / 4GB（现网） |
|---|---|---|---|
| discovery | 3000 | 372 次/秒，0.21s / 0.98s | 368 次/秒，0.22s / 0.92s |
| JWKS | 2000 | 329 次/秒，0.22s / 0.95s | 353 次/秒，0.21s / 0.88s |
| 登录页渲染 | 1000 | 33 次/秒，2.9s / 4.6s | 78 次/秒，1.1s / 2.2s |
| 密码登录（password grant） | 600 | 11 次/秒，8.2s / 10.7s | 21 次/秒，4.4s / 5.6s |
| M2M（client_credentials） | 600 | 90 次/秒，0.88s / 1.4s | 98 次/秒，0.86s / 0.95s |

瓶颈是 CPU（密码哈希 + 页面渲染）：登录类场景在两种规格下都会冲到 100%，吞吐随
vCPU 近似线性增长；内存峰值 1 vCPU 时 43%、2 vCPU 时 18%。discovery/JWKS 两种
规格持平，受网络与 API Gateway 限制，与 CPU 无关。

**模型网关**（LiteLLM 单 worker，跑在 1 vCPU 实例 → Bedrock us-west-2）：
800 请求零失败，Bedrock 侧零 throttle：

| 场景 | 请求数 | 吞吐 | 总耗时 p50 / p99 | 首包 p50 / p90 |
|---|---|---|---|---|
| 对话 · 短提示 | 100 | 14.6 次/秒 | 5.3s / 6.8s | 1.3s / 6.2s |
| 对话 · ~5K token 上下文 | 200 | 12.9 次/秒 | 6.9s / 11.2s | 3.5s / 7.5s |
| embedding | 500 | 152 次/秒 | 0.64s / 0.75s | — |

单请求基线首包约 1.3s；两波突发期间代理逐秒采样 CPU 持续 100%，首包排队
来自代理而非模型。Bedrock 配额余量充足：kimi-k3 跨区推理 2000 万 TPM
（100 人同时跑 Agent 估算峰值不超过约 900 万），titan-embed-v2
6000 RPM / 30 万 TPM。

### 判读与活动前动作

两者都**扛得住 100 并发**（零错误），代价是同步突发时排队：中央 Keycloak 扩到
2 vCPU 后，100 人同一秒登录每人等约 4~6 秒（1 vCPU 时 8~11 秒）；模型网关 100 路
推理同时发起，首包排到 6~7 秒。

1. **中央 Keycloak 已提到 2 vCPU / 4GB**（2026-10-09，数据见上表）。单副本只能
   纵向扩容；想把 100 人同时登录压到约 2~3 秒，可再提到 4096/8192（费用再翻倍）。
   活动结束后回落到 1024/2048 省一半 Fargate 费用。命令（其余参数沿用栈上旧值）：

   ```bash
   aws cloudformation deploy --template-file part2_chat_portal/infra/keycloak-fargate.yaml \
     --stack-name <中央 KC 栈名> --capabilities CAPABILITY_NAMED_IAM \
     --region cn-northwest-1 --parameter-overrides TaskCpu=2048 TaskMemory=4096
   ```

   ⚠️ 改规格会替换任务：新旧任务短暂并存（服务默认先起新、再停旧），且 realm
   不含密钥材料，新任务会重新生成签名密钥——**已签发的 token 全部失效，在线用户
   需重新登录**（门户提示 401/403 时重新登录即可）。所以要在无人使用时执行，执行后
   核对 discovery 的 issuer 未变、四种登录都能拿到 token。任务因故重启（如 Fargate
   维护）同样会导致全员重新登录，活动中留意。

2. **模型网关代理换 4 vCPU 并以多 worker 启动**（如 `litellm --num_workers 4`）。
   ⚠️ 若代理实例没有弹性 IP、CloudFront 回源写的是实例公网 DNS，停机换规格会
   换公网 IP、网关直接断——先分配并关联弹性 IP（关联瞬间原公网 IP 即失效），
   **同时**把 CloudFront 回源改为弹性 IP 的公网 DNS，再停机改实例类型。
