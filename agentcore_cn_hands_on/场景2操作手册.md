# 场景 2 操作手册：Web Chat 分析门户

本手册是[场景 2 介绍](场景2介绍.md)的动手部分。**全部操作都在场景 1 用过的
浏览器版 IDE 里完成**（打开门户页面除外）。

## 前置检查

- 场景 1 已跑完（`02_run_scenario1.sh` 成功）：本场景的部署脚本要读取场景 1
  的 Runtime ARN，任务管理模块也要调度场景 1 的 Agent
- 模型 key 已就绪（同场景 1：全球区 `AWS_BEARER_TOKEN_BEDROCK`，
  中国区/自定义端点三元组）
- Keycloak 的基础设施骨架（ECS Fargate 0 副本待命 + API Gateway HTTPS 入口）
  已随 CloudLab 栈预建好，本场景只推镜像并拉起，无需额外准备
- 想好门户怎么打开（下文第 2 步三选一）；用 SSM 端口转发的话，笔记本上要有
  AWS CLI + Session Manager 插件

| 步骤 | 耗时（约） |
|------|-----------|
| 1. 一键部署 | 8-12 分钟 |
| 2. 打开门户并登录 | 2 分钟 |
| 3. 三类分析对话 | 10-15 分钟 |
| 4. 长期记忆演示（可选，需 `MEM0_*`） | 10 分钟 |
| 5. 任务管理 + 浏览器实况 | 10-15 分钟（单商品处理 2-5 分钟） |

## 第 1 步：一键部署

IDE 菜单（左上 ≡）→ Terminal → New Terminal：

```bash
# 模型 key（全球区示例；中国区改 export 三元组）
export AWS_BEARER_TOKEN_BEDROCK=<ABSK开头的key>

# 可选：启用 mem0 长期记忆（不 export 也能部署，记忆整体禁用、对话不受影响；
# 想做第 4 步的记忆演示就配上——需要一个 OpenAI 兼容端点做事实提取与 embedding）
# export MEM0_LLM_MODEL=... MEM0_LLM_BASE_URL=... MEM0_LLM_API_KEY=... MEM0_EMBEDDER_MODEL=...

bash ~/environment/agentcore_cn_workshop/scripts/03_run_scenario2.sh
```

脚本包装 workshop 原版 Part 2 一键部署（幂等，可重跑），依次完成：Keycloak
镜像构建推送并拉起 Fargate 服务 → 数据面 Lambda（记忆向量 + 通用 db Lambda）→
Gateway 及 3 个 MCP 工具注册 → Identity OAuth2 credential provider → 分析
Agent 部署到 Runtime（JWT 入站认证）→ 生成前端配置 → 任务管理模块（Tasks
HTTP API + 两个 Lambda + 调度组）。部署完预装前端依赖；不做自动冒烟。

一个「看起来像问题但不是」的现象：

- 首次运行任务栈会被部署两遍——两个 Lambda 的执行角色先建、函数就绪后再补
  HTTP API 调用许可，预期行为，重跑不会再出现

部署机密（demo 账号密码、Keycloak admin 密码、M2M client secret）首次生成后
存放在 `part2_chat_portal/.deploy/secrets.env`（已 gitignore），重复部署会复用。

## 第 2 步：打开门户并登录

先在 IDE Terminal 启动前端：

```bash
cd ~/environment/agentcore_cn_workshop/part2_chat_portal/web && npm run dev
```

登录页由 Keycloak 提供，访问方式三选一（取决于部署 IDE 栈时的开关）：

| 方式 | 前提 | 打开地址 | 说明 |
|------|------|---------|------|
| A · 公网 HTTPS | 栈带 `ENABLE_PUBLIC_PORTAL=1` | 栈输出 `PortalUrl`（`https://<alb-dns>:8443`） | 自签证书首次访问点「高级 → 继续前往」 |
| B · SSM 端口转发 | 默认可用，零公网暴露 | `http://localhost:5173` | 笔记本上先转发（见下） |
| C · 公网 HTTP | 栈带 `ENABLE_HTTP_PORTAL=1` | 栈输出 `HttpPortalUrl`（`http://<nlb-dns>:5173`） | 中国区最顺滑（免备案免证书告警）；前端自动退回无 PKCE 授权码流程。⚠️ token 明文，仅限演示 |

方式 B 的端口转发命令（`<instance-id>` 见栈输出 `IdeInstanceId`）：

```bash
aws ssm start-session --target <instance-id> --region us-west-2 \
  --document-name AWS-StartPortForwardingSession \
  --parameters '{"portNumber":["5173"],"localPortNumber":["5173"]}'
```

**获取登录密码**——密码在第 1 步部署时自动生成，存放在 IDE 内的
`part2_chat_portal/.deploy/secrets.env`（已 gitignore，重复部署会复用）。
IDE Terminal 里执行：

```bash
grep -E 'ANALYST_PASSWORD|VIVIAN_PASSWORD|MARCO_PASSWORD' \
  ~/environment/agentcore_cn_workshop/part2_chat_portal/.deploy/secrets.env
```

登录账号：

| 账号 | 密码变量 | 人设 | 用途 |
|------|---------|------|------|
| `analyst` | `ANALYST_PASSWORD` | 基线，无预置记忆 | 主力体验账号；记忆演示里做现场沉淀 |
| `vivian` | `VIVIAN_PASSWORD` | 资深买手（美国站、人民币、月销 ≥ 50） | 记忆对比演示 |
| `marco` | `MARCO_PASSWORD` | 风控合规（英镑原币、必查合规、表述保守） | 记忆对比演示 |

> Keycloak 管理台（可选）：`部署输出的 Keycloak 地址 + /admin/`，账号 `admin`，
> 密码取法相同：
>
> ```bash
> grep KC_ADMIN_PASSWORD ~/environment/agentcore_cn_workshop/part2_chat_portal/.deploy/secrets.env
> ```

## 第 3 步：三类分析对话

用 `analyst` 登录，按顺序体验，边用边对照介绍里的时序图想「这次调用走到了
哪一步」：

1. **固定报表**：点侧栏「选品漏斗」或「类目分布」——Agent 调 Gateway 的预置
   MCP 工具查数仓，流式返回表格和图表。
2. **即席分析**：输入框直接提问，例如
   `候选池里产品点最高的 5 个商品是什么？给出价格、月销和预估售价`。
   Agent 把问题转成只读 SQL（只允许 SELECT、单条语句、最多 500 行）再做统计。
3. **会话内多轮**：接着追问 `第一名的商品为什么判 PASS？`。历史是两层的：
   先命中 Runtime 沙箱里的内存历史；沙箱被回收（空闲约 15 分钟）或被重新部署
   顶掉后，从数仓的会话表回灌，上下文不断档。
4. **历史会话**：侧栏按最后活动时间倒序列出**当前登录用户自己的**会话，点一条
   回看完整对话并可接着追问；悬停可重命名/删除（软删，消息在数仓保留）。

## 第 4 步：长期记忆——三个分析师的对比演示（可选）

前置：第 1 步部署时配置了 `MEM0_*`。先预置人设记忆（幂等，可重跑；需要与部署
时同一套 `MEM0_EMBEDDER_*` 环境变量）：

```bash
cd ~/environment/agentcore_cn_workshop/part2_chat_portal
python3 scripts/seed_memories.py
```

脚本给 `vivian` 和 `marco` 各写 5 条偏好事实，`analyst` 刻意留空。演示流程：

1. **vivian 登录**，侧栏底部点「长期记忆 mem0」徽标展开记忆面板，确认 5 条
   预置偏好；然后问一个**不带任何口径**的问题：
   `看下已有判定记录里的价格分布，按判定结果分组给我看看均价`。
   回答开头会列出自动套用的筛选口径（仅 US 站、月销 ≥ 50、换算人民币）——
   问题本身一个字没提，全部来自记忆注入。
2. **切换 marco** 问同一个问题：口径完全不同（英镑原币、注明汇率、结论附数据
   来源）；他的记忆面板里是自己的 5 条，与 vivian 互不可见。
3. **analyst 现场沉淀**：告诉它
   `记住我的分析偏好：金额一律换算成人民币，我只关注英国站`，等流结束
   （mem0 后台提取，输入框解锁会晚几秒），点「新对话」再问业务问题——偏好
   已生效，面板里能看到新条目。

> 记忆在**新会话首轮**注入（当前会话内靠上下文本来就记得），所以新沉淀的记忆
> 要点「新对话」后才能看到效果。命令行验证用
> `./scripts/memory_test.sh`（数据面冒烟）或 `--e2e`（跨会话回忆全链路）。

## 第 5 步：任务管理——在门户里调度场景 1 的 Agent

门户侧栏「任务管理」把场景 1 的命令行调用搬到了页面上。链路独立、不经过
Gateway：任务页用同一份用户 token 调 Tasks HTTP API（JWT authorizer）→
tasks-api Lambda 管任务表和调度 → runner Lambda 用自己的执行角色 SigV4 签名
调用场景 1 的 Runtime——**AWS 凭证不下发前端**。走一次完整流程：

1. **新建一次性任务**：点「新建任务」，站点选 `UK`，摄入指令填：

   ```text
   从 eBay 英国站搜索 storage box 选品，按 Best Match 顺序处理前 2 个非广告、一口价、全新商品；跳过广告、拍卖、二手和翻新商品且不占名额。严格按 product-selection-ebay SOP 判定并逐个入库。
   ```

   调度模式选「一次性 · 创建后立即执行」。
2. **看进度时间线**：点进最新运行记录，页面每 3 秒增量刷新，时间线里会出现
   `skills`、`browser`、`code_interpreter` 等工具调用，右侧「关键日志」是
   Agent 的流式输出。每次运行有独立的 Runtime 会话，并行任务互不干扰。
3. **打开 DCV 浏览器实况**：趁状态还是「运行中」，点顶部「打开实况」——通过
   Amazon DCV 直连 AgentCore 托管的 Chromium，**实时**看到 Agent 正在访问的
   eBay 页面（不是录屏）。链接由服务端签名、300 秒有效，过期点「刷新重连」；
   运行结束 Browser 会话销毁，实况自然关闭。按钮没出现就等时间线里的
   「云端浏览器会话已就绪」。
4. **复盘入库结果**：运行结束后看顶部的候选数、判定分布与耗时；「本次入库
   明细」的「候选商品」「选品判定」两个 tab 对应 `product_candidates` /
   `selection_verdicts`。`PASS` 表示未过 R1 硬门槛已丢弃，真正入候选池的是
   「采集」；只有「补采」记录说明页面抓取失败，是如实记录不是故障。
5. **可选：定期任务**：模式改「定期」，预设「每 N 小时」「每天定时」，或
   自定义 `rate(30 minutes)` / `cron(0 9 * * ? *)`；可暂停/恢复调度，删除任务
   保留历史运行。快速验证调度用 `rate(5 minutes)`。

> 单个商品完整处理约 2-5 分钟。想现场看 DCV 画面，建议一次处理 2 个商品，
> 提交后立刻进运行详情。

## 可选：命令行冒烟

不开前端也能模拟完整调用链（换 token → SSE 流式调用 Runtime）：

```bash
cd ~/environment/agentcore_cn_workshop/part2_chat_portal
./scripts/chat_test.sh '看下最近30天的选品漏斗'
# 多轮：把上一次输出的 session id 作为第二个参数
./scripts/chat_test.sh '候选池里产品点最高的5个商品' <session-id>
```

## 动手观察点

1. **验证 audience 隔离**：`chat_test.sh` 的输出里能看到先向 Keycloak 换用户
   token、再流式调用 Runtime 的两步；对照介绍里的时序图，想想为什么这个 token
   直接去调 Gateway 会被拒（Gateway 的 authorizer 只收 `aud=analysis-gateway`）。
2. **验证会话回灌**：一个会话聊几轮后放置 15 分钟以上（沙箱被回收），回来接着
   追问上文细节——上下文不断档，因为 Agent 从数仓的会话历史表回灌了完整消息。
3. **验证记忆隔离**：vivian 和 marco 同题不同答、且互相看不到对方的记忆面板；
   底层向量就在 Aurora pgvector 里，可用运行手册里的 db Lambda 查询命令直接看。
4. **看一次全组件协同**：任务详情页同屏观察 DCV 实况（Browser）、进度时间线
   （Runtime 流式事件）和入库明细（写库 Lambda → Aurora）——这一屏正好把两个
   场景的全部 AgentCore 组件串在了一起。

## 排障速查（场景 2 相关）

| 症状 | 处理 |
|------|------|
| 部署冒烟 403 | Keycloak 刚拉起需约 1 分钟就绪；重跑 `03_run_scenario2.sh`（幂等，会同步 authorizer） |
| 门户空白页 / redirect_uri 报错 | 用手册列出的三种入口之一（`localhost`、`PortalUrl`、`HttpPortalUrl`），不要用机器 IP 直连 5173 |
| 方式 C 登录报错 | Keycloak 若在 realm 放开 PKCE 之前部署过，`KC_REDEPLOY=1` 重跑 `03_run_scenario2.sh` 重建 realm |
| 调用 401 invalid_api_key | 模型 key 失效或用了 `sk-` 假 key；换 `ABSK` key 后重跑 03（key 会烧进 Runtime 环境变量） |
| docker permission denied | 重开一个 Terminal（ec2-user 已加入 docker 组，新会话生效） |
| 记忆没生效 | 确认部署时已配 `MEM0_*`；新沉淀的记忆要点「新对话」后才注入；`./scripts/memory_test.sh` 做数据面冒烟 |
| Live View 打不开 / 410 | 运行结束后 Browser 会话已销毁属正常；运行中 300 秒链接过期点「刷新重连」 |

更全的排障见[运行手册](运行手册.md)排障速查与 `agentcore_cn_workshop/实验手册.md`。
