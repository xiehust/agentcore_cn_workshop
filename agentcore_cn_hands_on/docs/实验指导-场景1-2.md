## 1. 准备模型 key（两个场景的唯一前置）

两个场景的 Agent 都通过 OpenAI 兼容端点调用 **OpenAI GPT-5.6**（默认走
bedrock-mantle），认证用 **Bedrock API key**（`ABSK` 前缀的长期 key）：

1. 登录 AWS 控制台 → **Amazon Bedrock**（默认模型端点在 **us-east-1**，
   建议在 us-east-1 操作）；
2. 左侧 **Model access** → 确认 **OpenAI GPT-5.6** 已开通（未开通则申请，
   即时生效）；
3. 左侧 **API keys** → **Generate long-term API key** → 复制 `ABSK` 开头的 key
   （只显示一次，保存好）。

回到 IDE Terminal，导出（**后续 02/03 都要在同一个 Terminal 会话里跑**，
新开 Terminal 需要重新 export）：

```bash
export AWS_BEARER_TOKEN_BEDROCK=<粘贴ABSK开头的key>
```

> 中国区/自定义端点的替代方式：`export OPENAI_BASE_URL=<https://.../v1>
> OPENAI_API_KEY=<key> MODEL_ID=<模型名>`（任意 OpenAI 兼容 Chat Completions 服务）。

## 2. 场景 1：选品数据摄入 Pipeline（约 10 分钟）

**链路**：你（CLI）→ AgentCore **Runtime**（Strands Agent + 选品 SOP Skill）→
**Browser** 爬 eBay（Web Bot Auth 过反爬）/ **Code Interpreter** 沙箱测算产品点 →
写库 Lambda → Aurora。

### 2.1 一键部署 + 冒烟

```bash
bash ~/environment/agentcore_cn_workshop/scripts/02_run_scenario1.sh
```

脚本做四件事，预期输出节奏：

| 阶段 | 内容 | 耗时 |
|------|------|------|
| [a] | 创建自定义 Browser（Web Bot Auth）+ Browser Profile | ~1 分钟（新建 IAM 角色有生效等待，重试属正常） |
| [b] | `agentcore configure/launch` 部署 `product_ingestion_agent` 到 Runtime | 2-4 分钟 |
| [c] | 给 Runtime 执行角色附加写库/浏览器策略 | 秒级 |
| [d] | **真实冒烟调用**：爬 eBay 英国站 1 个商品 → 测算 → 入库 | 2-5 分钟 |

成功标志：冒烟结束后脚本会**自动打印本次新增的入库记录**
（`════ 冒烟测试结果：本次新增的入库记录 ════` 段落，逐字段展示商品标题、
判定、理由、价格等），末尾 `✅ 场景 1 冒烟调用完成`。

> 不想等冒烟：`SKIP_SMOKE=1 bash ~/environment/agentcore_cn_workshop/scripts/02_run_scenario1.sh`

### 2.2 自己玩几次调用（可选）

**方式一（推荐）：包装脚本**——自动激活环境、调用结束自动展示本次新增的入库记录：

```bash
bash ~/environment/agentcore_cn_workshop/scripts/invoke_verify.sh '从 eBay US（ebay.com）搜索 desk organizer 选品，处理前 2 个非广告一口价商品，按选品 SOP 完成判定并入库'
```

只回看最近入库记录（不调用 Agent）：

```bash
bash ~/environment/agentcore_cn_workshop/scripts/invoke_verify.sh --recent 60
```

**方式二：直接用 `agentcore invoke` 原生命令**。注意 `agentcore` 装在
workshop 的 Python venv 里，**新开的 Terminal 必须先激活 venv、并进入 agent
目录**，否则会报 `bash: agentcore: command not found`：

```bash
# ① 激活 venv（每个新开的 Terminal 都要先做一次）
source ~/environment/agentcore_cn_workshop/.venv/bin/activate

# ② 进入 agent 目录（invoke 靠该目录下的 .bedrock_agentcore.yaml 定位 Runtime）
cd ~/environment/agentcore_cn_workshop/part1_data_ingestion/agent

# ③ 调用（prompt 需包成 JSON；invoke 本身不需要模型 key——key 已烧进 Runtime）
agentcore invoke '{"prompt": "从 eBay 英国站搜索 desk organizer 选品，按 Best Match 顺序处理前 2 个非广告、一口价、全新商品；跳过广告、拍卖、二手和翻新商品且不占名额。严格按 product-selection-ebay SOP 完成页面取数、月销估算、市场结构与黑名单判定、Code Interpreter 经济测算，并对每个已处理商品立即调用 save_verdict 入库；判定为采集时再调用 save_candidate。抓取失败按 SOP 写补采，不得编造数据。最后汇总处理数、各 verdict 数量、入库结果和候选产品点。"}'

# ④ 查看这次的入库结果
bash ~/environment/agentcore_cn_workshop/scripts/invoke_verify.sh --recent 30
```

更多示例 prompt（关键词搜索/类目浏览/单 URL 判定）见
`part1_data_ingestion/scripts/invoke_example.sh`。每个商品 2-5 分钟。

### 2.3 常见问题

| 现象 | 处理 |
|------|------|
| `bash: agentcore: command not found` | `agentcore` 装在 workshop 的 venv 里，新 Terminal 未激活时找不到——先 `source ~/environment/agentcore_cn_workshop/.venv/bin/activate`（见 2.2 方式二），或直接用 `invoke_verify.sh`（脚本内部自动激活） |
| 调用 401 invalid_api_key | key 失效或非 ABSK；换 key 后**重跑 02**（key 烧进 Runtime 环境变量，必须重新 launch） |
| 冒烟超时 | 单商品 2-5 分钟属正常；prompt 里减少处理数量 |
| `等待 IAM 角色生效后重试` 刷了几轮 | 正常，新角色全区域可见有延迟 |

## 3. 场景 2：Web Chat 分析门户（约 20 分钟）

**链路**：浏览器 SPA（Keycloak 登录）→ Runtime（分析 Agent，JWT 入站）→
Identity（M2M）→ **Gateway**（MCP 工具）→ Lambda(VPC) → Aurora；
另含 Code Interpreter 统计分析、mem0 长期记忆、任务定时调度。

### 3.1 （可选）启用长期记忆 mem0

不配置则记忆功能禁用、对话不受影响。要体验多账号记忆演示的话，部署前 export
（LLM 与 embedding 均为 OpenAI 兼容端点，四个必填）：

```bash
export MEM0_LLM_MODEL=<模型名> MEM0_LLM_BASE_URL=<https://.../v1> MEM0_LLM_API_KEY=<key>
export MEM0_EMBEDDER_MODEL=<embedding模型名>
# 可选：MEM0_EMBEDDER_BASE_URL / MEM0_EMBEDDER_API_KEY / MEM0_EMBEDDER_DIMS（默认1024）
```

### 3.2 一键部署 + 冒烟

确认模型 key 还在当前 Terminal（`echo $AWS_BEARER_TOKEN_BEDROCK`），然后：

```bash
bash ~/environment/agentcore_cn_workshop/scripts/03_run_scenario2.sh
```

脚本预检后调用 workshop Part 2 部署（Keycloak 镜像构建推送 → **拉起 base 栈
预建的 Keycloak 服务**（基础设施已随 CloudLab 栈建好，0 副本待命，此处只做
镜像推送和扩容到 1 副本）→ 3 个数据面 Lambda → Gateway → Identity →
分析 Agent → 任务模块），首次约 8-12 分钟，**任务栈部署两遍是预期行为**。
Keycloak 管理员密码由 base 栈的 Secrets Manager 生成，部署时自动同步进
`.deploy/secrets.env`。末尾预装前端依赖；不做自动冒烟，需要命令行验证时
手动执行 `part2_chat_portal/scripts/chat_test.sh '你的问题'`。

### 3.3 启动前端

```bash
cd ~/environment/agentcore_cn_workshop/part2_chat_portal/web && npm run dev
```

保持这个 Terminal 开着（前端进程），后续操作新开一个 Terminal。

### 3.4 打开门户

本环境是 default 形态（无公网门户），用 **SSM 端口转发**（本机需 AWS CLI +
Session Manager 插件）：

```bash
aws ssm start-session --target i-07fd26fd6d98dbfbd --region us-west-2 \
  --document-name AWS-StartPortForwardingSession \
  --parameters '{"portNumber":["5173"],"localPortNumber":["5173"]}'
```

保持该窗口开着，浏览器打开 `http://localhost:5173`。

> 想改用公网门户：操作员机器上带 `ENABLE_HTTP_PORTAL=1`（HTTP/NLB，免告警）
> 或 `ENABLE_PUBLIC_PORTAL=1`（HTTPS/ALB，自签证书一次告警）重跑
> `ide/deploy-ide.sh`，栈输出会多出 `HttpPortalUrl` / `PortalUrl`；
> 再重跑一次 `03_run_scenario2.sh` 同步 Tasks API 的 CORS 白名单。

**登录账号**：`analyst`（基线）。密码在 IDE Terminal 里查：

```bash
grep ANALYST ~/environment/agentcore_cn_workshop/part2_chat_portal/.deploy/secrets.env
```

### 3.5 上手体验

对话页试试：

- 「看下最近30天的选品漏斗」（Gateway MCP 工具查数仓）
- 「按站点统计通过率，算一下均值方差」（Code Interpreter 统计分析）

**任务页**：把场景 1 的摄入做成一次性/定时任务（EventBridge Scheduler →
runner Lambda → 场景 1 Runtime），可看运行进度与 Browser Live View。

**长期记忆演示**（需 3.1 已配置）：先预置两个人设账号的记忆——

```bash
cd ~/environment/agentcore_cn_workshop/part2_chat_portal && python3 scripts/seed_memories.py
```

再分别用 `vivian`（资深买手）、`marco`（风控合规）登录（密码同样在
`secrets.env`），问同一个问题（如「给我推荐下一批选品方向」），观察回答差异。

### 3.6 常见问题

| 现象 | 处理 |
|------|------|
| 登录页报 `Invalid parameter: redirect_uri` | 旧 Keycloak 镜像，`KC_REDEPLOY=1 bash ~/environment/agentcore_cn_workshop/scripts/03_run_scenario2.sh` |
| 门户空白卡住 | 用了 `http://<IP>:5173` 直连？走上表三种方式之一 |
| 会话/任务列表 `Failed to fetch` 但对话正常 | Vite 没跑在 5173（端口被占自动换号）——释放 5173 重启前端 |
| 冒烟/对话 403 | Keycloak 刚就绪等 1 分钟重试；或重跑 03（幂等，同步 authorizer） |
| 部署报 docker 权限 | 重开一个 Terminal（docker 组新会话生效） |

## 4. 验证数据入库（随时可查）

通用数据面 Lambda `agentcore-workshop-db` 已随步骤 01 部署，任意 SELECT 都能查：

```bash

  --cli-binary-format raw-in-base64-out \
  --payload '{"op":"execute","args":{"sql":"SELECT product_title, verdict, reason, current_price, created_at FROM selection_verdicts ORDER BY created_at DESC LIMIT 5","params":{}}}' \
  /dev/stdout
```

更省事的方式是 `invoke_verify.sh --recent 60`（见 2.2）。
能看到冒烟处理过的 eBay 商品与判定记录即闭环。
