# 从 Demo 到生产：基于 Amazon Bedrock AgentCore 构建跨境电商选品 Agent

过去一年，AI 应用的形态正在从"对话问答"走向 "Agent"：LLM 不再只是回答问题，而是自主规划任务、调用工具、操作浏览器、执行代码，端到端地完成一件真实的工作。Strands、LangGraph、CrewAI 等开源框架让写出一个 Agent 变得很容易——真正的挑战在后面：Agent 要在哪里运行？浏览器和代码执行这类高风险工具怎么安全托管？Agent 以什么身份访问企业内部系统？这些"从 demo 到生产"的问题，光靠 Agent 框架本身解决不了。

[Amazon Bedrock AgentCore](https://aws.amazon.com/bedrock/agentcore/) 就是 AWS 对这一层问题的回答——面向生产级 AI Agent 的托管基础设施家族，让你可以把任意框架（Strands、LangGraph、CrewAI……）编写的 Agent 直接部署成安全、可扩缩的云端服务。它由一组各司其职的组件构成——**Runtime**（会话级隔离、按需扩缩的无服务器 Agent 运行时）、**Browser**（云端托管的真实 Chromium 浏览器）、**Code Interpreter**（安全代码执行沙箱）、**Gateway**（托管的工具网关，把存量 API/Lambda 转换成 MCP 兼容工具并聚合到统一 MCP 端点，自带出入站认证）、**Identity**（Agent 的入站认证与出站授权）——你只编写 Agent 的业务逻辑，生产化的重活全部交给托管服务。

你可以把 AgentCore 理解为 "Agent 界的 Serverless"：正如 Lambda 让你不用关心服务器就能跑代码，AgentCore 让你不用关心运行时隔离、浏览器基础设施、沙箱环境和凭证管理，就能把一个 Agent demo 变成生产服务。

这些问题具体长什么样？在笔记本上用脚本跑通一个 Agent demo 并不难，但要把它变成对外提供服务的生产系统，问题就变了：

* 运行时：单次 Agent 任务动辄运行数分钟，调用量随任务波动，你需要会话隔离、按需扩缩的托管运行时，而不是自己维护一个常驻服务器
* 工具安全：Agent 操作浏览器爬取网站要通过 Cloudflare/Akamai 的反爬校验；LLM 生成的代码绝不能直接跑在生产环境里，必须进沙箱执行
* 身份与集成：终端用户要认证登录，Agent 访问内部数据接口需要自己的机器凭证（不能把数据库密码交给大模型），存量的 Lambda/API 还要用标准协议暴露成 Agent 能调用的工具

这些正好逐一对应 AgentCore 的各个组件。本 Workshop 用一个贴近真实业务的场景把它们全部串起来：**跨境电商选品**。设想你每天要在 eBay 上翻几十个商品页，记录价格、销量、卖家信息，套用选品 SOP 做经济测算，把值得跟进的候选品录入数据库——我们将构建一个基于开源框架 [Strands Agents](https://strandsagents.com/) 的 Agent 来接管这套流程：它用 AgentCore **Browser** 爬取商品页、在 **Code Interpreter** 沙箱里执行测算公式、把判定结果写进 Aurora 数仓，整体托管在 **Runtime** 上；选品 SOP 以 Skill（一份 `SKILL.md`）的形式插拔，以后做竞品监控、价格追踪只需换一份 Skill，Agent 代码零改动。

本 Workshop 将带你在浏览器版 VS Code IDE 中，通过分步脚本完成两个连贯实验：**场景 1** 部署选品数据摄入 Pipeline（Runtime + Browser + Code Interpreter），**场景 2** 部署 Web Chat 分析门户，运营同学登录后用自然语言直接分析入库数据（Runtime + Gateway + Identity，含自部署 Keycloak 认证与 mem0 长期记忆）。IDE、数仓与全部实验资源由一个 CloudFormation 栈承载，删除栈即可一键销毁。整套代码全球区与中国区通用，区域（`AWS_REGION`）是唯一开关。
